## 二、★ 修改语义的三次演进（最关键的纠正）

这是 Owner **两次纠正**才定下来的，务必理解清楚。

### 第一版（我理解错了）：原地修改
我最初做成「格子提交后可以原地编辑」。
**Owner 纠正 1**：

> 「每一个都只是唯独提交了不能改。要改是重新新开一个个表单……
> 在前一个记录跟后一个记录增加一个关联。词针里边的关键词吧。」

我据此改成：Panel 级 `correlationId` + 词典实体关键词。

### 第二版（还是没完全对）：界面级关联
Owner 又纠正（这条是分水岭）：

> 「我说的关键词是在两件单单子收过来的时候，前一段跟后一站有一些关键的信息去串联那个。
> 两个单子之前说第一个单子，如果提交了，就已经确认不能改了。然后面再改的时候，就是新的单子啊。」

**→ 定稿语义**：

1. 关键词不是界面父子关系，是**两张独立订单之间的业务关键字段串联**
2. 已确认的订单**不能改**，再改 = **另开一张新单号**
3. 两单用 `originNo` / `supersededByNo` / `chainId` **双向互指**
4. 草稿单可以原地「修订」（因为它还没生效）

这就是真实 ERP 的**变更单**模式。详见 `03_VERBS.md`。

> **教训**：Owner 说「关联」时，先问清楚是**界面级**还是**业务级**。
> 他关心的是业务语义，不是 UI 结构。

### 关于 DeepSeek V4 Flash 的 401

Owner 此前在别的工具上遇到过 `deepseek-v4-flash` 返回 401。
本项目的连通性测试会**返回服务端原始错误**，实测假 Key 的返回是：

```
HTTP 401 · 鉴权失败（key 无效 / 无该模型权限 / endpoint 不匹配）

         "message":"The API key format is incorrect...","type":"Unauthorized"}}
```

> 骨干的"躯干"= Agent Harness：不生产智能，负责让脑袋的决策**持续、可控、可恢复地**传到四肢（工具/应用）。

### 感官清单（开放枚举，加官不改协议）

| modality | 辨认器 | 当前状态 |
|---|---|---|
| `text` | 无（原生） | ✅ 键盘 / 输入法 —— **已有，最易被忽略的一官** |
| `audio` | ASR | ✅ **两只耳朵、一种 modality**：`browser`（Web Speech，默认）/ `local`（SenseVoice int8 229MB，服务端 `POST /api/asr`）。辨认器由 `asrEngine` 选，**协议与 `/api/interpret` 一字未动**（同 `speak.ts` 的「嘴」） |
| `image` | OCR（远期 VLM） | 🔴 远期 |
| `touch` | 力/触觉传感 + 设备控制 | 🔴 远期（机器人 / 自动驾驶） |
| `thermal` / `smell` / … | 各自传感器 | 🔴 远期，仅预留 |

**关键原则**：所有感官在协议里产出同一种东西 —— **Observation（观测）**：

```jsonc
{ "modality": "audio", "source": "mic-01", "at": "ISO8601",
  "payload": "辨认后的结构化结果", "confidence": 0.87, "raw": "原始信号引用" }
```

加一个新感官 = 加一种 `modality` + 一个辨认器，**不动协议结构**。
三层拆分：**采集**（换硬件才改）→ **辨认**（换辨认器才改）→ **决策**（永远不改）。
控制是感知的镜像：Observation（进）· Action（出，= 12 动词）· Run（中间状态）。
（现行同构先例：x-agent 的 `resolution` 字段 —— 加消解策略不动架构。）

- ⛔ **现在不建主仓 repo** —— Agent_ERP 闭环今天才首次真跑通（T1），T2/T3/T4 未做；守「核心闭环未通不加第二个大功能」

## 十二、记忆的写入策略：候选区 + 跨天阈值（2026-09-07 Owner 定）

**问题**：一次点击就把说法写进个人用语表，会把口误 / ASR 噪声当习惯（如「老呃张老」）。
**Owner 的原话**：「如果某一次他说『老张』或『老呃张老』，那可能只是不小心说的，不一定是一个标准的需求。」

### 三层结构

```
① 观察  candidate   说法出现 → 记一笔证据（不参与消解，绝不自动生效）
② 证据  co-occur    与目标的共现次数 + 跨天数
③ 升格  active      达到阈值 → 转正式记忆卡，画布提示「我注意到你常说 X，要记住吗？」
```

### 升格阈值（三选一，Owner 选 B）

| 方案 | 规则 | 结论 |
|---|---|---|
| A · 计数 | 同一说法指向同一目标 ≥ 3 次 | ❌ 一天内连说 3 次也会升格 |
| **B · 跨天** ⭐ | **≥ 2 次 且 跨 ≥ 2 天** | ✅ **已采纳** —— 最能过滤"今天随口一说" |
| C · 仅显式 | 只有点「记住」才生效 | ❌ 等于现状，只是加提示 |

**为什么 B 能过滤噪声**：噪声的本质是**不稳定**（每次长得都不一样），永远累积不到跨天计数；
真别名的本质是**稳定重复**，自然会跨天累积。阈值即噪声过滤器。

### 节点网络从哪来（不新建图存储）

`Panel` 里已经躺着三样东西，网络是**派生**出来的，不是新建的：

| 图的部件 | 现有数据 |
|---|---|
| 节点 | `Panel.entities` = `[{type,value,label}]`（客户 / 产品 / 仓库 / 单号） |
| 共现边 | 同一 Panel 的 entities 两两相连 |
| 同对象边 | 相同 `Panel.correlationId` |
| 时序边 | 同 session 内按 `createdAt` 相邻 |
| 映射边 | `PersonalLexeme`：说法 → 目标 |

### 明确不做

- ⛔ 引入图数据库（Neo4j 等）—— 红线：不 clone 整包框架；SQLite 一张共现表足够
- ⛔ 接入 Obsidian / 建 vault —— 那是另一个应用，会让两个事实源打架
- ⛔ 向量检索 —— 决策 #13 已否决；这里要的是**计数**，不是相似度

### 排期

**T3 → T4 → 记忆网络 v1（candidate + 跨天升格）→ T5 抽 `core/`**。
守红线：核心闭环未通不加第二个大功能。

## 十三、记忆网络 v1 落地（2026-09-08）

| 部件 | 落法 |
|---|---|
| **候选区** | `PersonalLexeme.status` 新增 `candidate` —— 观察中，**不参与消解**（`lookupSlot` 只查 `active`） |
| **证据表** | 新增 `LexemeEvidence(phraseNorm, slot, targetId, day, source)`，唯一键 `(userId, phraseNorm, slot, targetId, day)` → 同一天同一目标只记一次 |
| **观察点** | 动词 `run` **成功**后，从 `slots` 取客户/产品的 `raw` + 提交值 → `observeUsage()`；**观察失败绝不影响主流程** |
| **升格** | `days ≥ 2` → `candidate` 转 `active`；点「记住」（`source: 'explicit'`）立即生效，不受跨天限制 |
| **噪声过滤** | 噪声每次长得都不一样 → 凑不满同一目标的跨天计数 → 自动沉底 |

复现：`npm run smoke:memory`（6 项断言）。
阈值常量：`PROMOTE_MIN_DAYS = 2`（`lexicon.ts`），改阈值只改这一个常量。

## 十四、「嘴」接进画布（2026-09-08 · A 项）

| 议题 | 结论 |
|---|---|
| 播报由谁发 | **服务端**（`POST /api/speak` → `src/server/speak.ts`）。前端各自喊会叠音，声音必须有一个 owner |
| 开关 | `TTS_ENABLED`（`.env.local`）+ 设置面板 Switch + 试听按钮；**默认开** —— 接进来就是为了让它主动说话 |
| 播报时机 | ① 执行结果（成功/警告/失败）② 还没问完的追问（语音场景下人不必盯屏） |
| 失败语义 | **只降级不抛错**：非 Windows / 缺 SAPI / 超时 → 打印文本并返回 `ok:false`。嘴缺位绝不能影响业务 |
| 并发 | 服务内**排队串行**（SAPI 一次只能读一句） |

### ★ 负知识：TTS 曾经是「假阳性」

| 现象 | 根因 |
|---|---|
| 改之前 `npm run say` 报「实测播报成功（exit 0）」，但**一个字都没念** | 原实现用 PowerShell **`-EncodedCommand`**，本机环境对它直接 **`spawn EPERM`**；而 `spawnSync` 的错误走的是降级分支（打印文本 + `exit 0`）—— **退出码 0 被当成了成功证据** |

**两条实测约束（写在 `speak.ts` 注释里，别改回去）：**

1. **禁用 `-EncodedCommand`**（AV / 策略常见拦截点）→ 改用 `-Command` + **单引号字面量内联**文本（内部 `'` 写成 `''`）
2. **`-Command` 不能配位置参数**：Windows PowerShell 5.1 会把多余参数原样拼进命令串（`… $s.Speak($args[0]) 中文测试` → `ParserError`）
3. 显式挑 `zh-*` 语音：默认语音可能是 `en-US`，中文会被念坏

**验收方法要改**：退出码 0 不算证据。本机用「合成到 wav」客观验证 —— 一句话生成 **230,820 字节** 的音频，才证明中文真在发声。

## 十六、「耳」接进画布：被测的耳朵 = 在用的耳朵（2026-09-09）

| 议题 | 结论 |
|---|---|
| 为什么非接不可 | 十五那个 **34.02%** 描述的是**一个候选引擎**，不是用户会遇到的表现：画布的语音输入是浏览器 Web Speech，`src/server/` 下**没有任何 ASR 路由**。数字与体感不同源，评测就只是自我安慰 |
| 怎么保证不出现两份实现 | **不给离线评测另写一份识别代码**。`scripts/asr-transcribe.ts` 删掉自带的 require + 构造，改为 `import` `src/server/asr.ts`。证明方式不是"看起来一样"：`npm run verify:asr` 把 39 条 wav 逐条 `POST /api/asr`，与 CER 报告的 hyp **逐字比 → 39/39 相同**；CER 因此**故意不重算**（重算就是第二份 `cer()` 实现） |
| 采集为什么在浏览器封 WAV | 服务端**没有 ffmpeg**，`MediaRecorder` 的 webm/opus 解不了；`decodeAudioData` 要多跑一趟编解码且产出 48k/立体声（3–6 倍字节）。`AudioContext({sampleRate:16000})` + ScriptProcessor 直采 16k，**顺带消掉 sherpa 每次调用往 stderr 刷的 `Creating a resampler`**。不上 AudioWorklet：要额外产物文件 + vite 构建耦合，而本用例每秒约 4 次 16KB 拷贝不构成主线程压力 |
| ★ **必须 `createAsync` / `decodeAsync`** | 实测：同步 `new OfflineRecognizer()` 期间 20ms ticker **走 0 次**（事件循环冻死），async 版走 **40 次**。冻住会连带卡死 `/api/interpret` 与静态资源。**这条别改回去**，注释已写在 `asr.ts` 头部 |
| 不做「卸载模型」按钮 | native 原型只有 `constructor,createStream,setConfig,decode,decodeAsync,getResult` —— **没有 free/destroy**。加载实测 **61→364MiB（+303MiB）不可回收**。兑现不了的按钮不做，改为把代价写进 UI 文案（面板：`加载后服务常驻约 XXXMiB，且不可回收`） |
| 默认引擎 = `browser`（Owner 定） | **默认态即回退态**：`asr.ts` 顶层零副作用 → 默认下 `/api/asr`、`voiceRecorder.ts` 全不被触达，连 native 包都不 require。三层回退任一层单独生效就回到接线前的行为：代码（默认 browser）/ 配置（面板或 `ASR_ENGINE=browser`，免重启）/ 物理（权重改名 → 恒 200 + `model_missing`） |
| 识别失败**不**回落另一只耳朵 | 会重新引入本轮要消灭的歧义 —— 分不清是哪只耳朵听错的字。`startVoiceLocal()` 失败只给可读文案（`ASR_REASON` 表），**绝不静默改用 Web Speech** |
| 文本规整落点 = `/api/interpret` 入口 | 不放 `asr.ts`：**浏览器引擎的文本同样要救**（Web Speech 一样会把型号听歪）。**→ 十七已落地** |
| 上传格式 | `application/octet-stream` 原始字节（**全仓第一个非 JSON body**）：比 base64 省 33%、免两端编解码、`curl --data-binary` 可直接手工复现。`bodyLimit` 2MiB≈65s；域内 15s 上限由 `asr.ts` 自己数（Fastify v5 **无 per-route bodyLimit**），回 `too_long` 而不是裸 413 |
| 并发不按「嘴」抄 | `speak.ts` 的串行队列理由是"SAPI 是外部单例资源"。async 解码不阻塞事件循环 → 改为 `inflight>=2 → busy`，防的是**并发加载两次 = 双倍 300MB** |
| 真人语料 | `PUT /api/asr/corpus/:id` → `eval/asr-wavs-real/<id>.wav`。安全边界（服务默认绑 `0.0.0.0`，这是个局域网可达的写盘口子）：id `^[A-Za-z0-9_-]{1,40}$`、只认 `RIFF`、`path.resolve` 后断言仍在该目录内、基目录硬编码不接受前端传入、默认 409 拒绝覆盖（`?overwrite=1` 才覆盖）。**含真人声音 → 不进 git**。实测：穿越 `%2F`/`%5C`/点号/超长全部 400，仓库内外都没长出野文件 |
| SenseVoice 不收热词 | `models/asr/hotwords.txt` 继续只当**文本规整词典原料**；`asr.ts` 里注释了一句，免得下次有人去接热词（十五已证：仅 transducer + `modified_beam_search` 支持） |

**本机实测（写进 `07_OPS` §六）**：加载 **853 / 1278 / 1466ms** · 39 条 HTTP `decodeMs` **p50=117 p90=156 max=188** · RTF **p50=0.039**（≈25 倍实时）· hyp **39/39 逐字一致** · 回归四闸门不劣化：`typecheck` 0 错误、规则 **96.2%/95.3%**、模型 **100%/100%**、真口吻 **97.4%**。

**诚实边界**：浏览器采音是全场**唯一不能命令行自证**的环节（本机无 ffmpeg，无头浏览器 `getUserMedia` 能否授权未知）。对策是让它可自证而不是假装测过：`encodeWav` 是纯函数（devtools 喂 `new Int16Array([1,-1,0])` 即可核对头 12 字节），「存为语料」之后同一段字节能在浏览器外用 `curl --data-binary` 复现。人工手测步骤见 `05_TEST_LOG`。

**验收口径要先对齐**：接上耳朵之后 34% CER **会立刻变成体感退化**（型号读法第一次真砸到体验上）。那不是回归，是"耳朵换对了"的证据；救它的是**文本规整**工单。
