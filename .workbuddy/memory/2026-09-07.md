## 01:00–01:20 · 端侧模型选型评估（语音输入为主场景）

产出：`.workbuddy/reviews/2026-09-07-语音输入模型选型评估.md`

### 名词对齐（重要，后续复用）
- 用户口中的「火星大模型 1.6B/1.8B」= **讯飞星火 X2.5 系列**（讯飞 2023 首发时叫「讯飞火星」，后改名星火）。2026-09-01 由子公司词元星火（XHToken）开源 **Spark-X2.5-1.7B / 4B**，Apache 2.0，原生 1M 上下文，Domux 指令执行 90.3%/0.85s，MCP-Atlas 23.4 同尺寸最高。4bit 后 ~1.0–1.2GB。

### 许可红线（本次最重要发现，跨项目适用）
- ✅ **Apache 2.0 可闭源分发**：Qwen3 全系、星火 X2.5 全系、sherpa-onnx、SenseVoice。义务仅为「附 LICENSE 文本」（放 About 页即可），**无 UI 署名要求**。
- ❌ **GLM-Edge**（智谱）：需商业登记 + **必须在 UI/文档显著显示 "Built with GLM-Edge"** + 衍生模型名加前缀 → 闭源软件出局。
- ❌ **MiniCPM**（面壁）：需登记 + **强制 "Built with 面壁MiniCPM"** + 端侧 ≤5000 台 / DAU<100万 才免费 → 出局。

### ASR 结论
- 主选 **sherpa-onnx + SenseVoice int8（229MB）**，Apache 2.0，Kaldi 之父 k2-fsa 团队，Rust 可静态链接（利 Tauri 打包），纯 CPU 主场。
- **关键坑**：FunASR/SenseVoice 官方 Python 包内嵌 ModelScope SDK，**即使模型在本地仍会尝试联网校验**（issues #2573/#1581/#1286），离线分发必须走 sherpa-onnx 转 ONNX。
- **热词是命门**：SenseVoice 热词基础准确率仅 **50.17%**（对比 FunASR-Nano 70.52%→加热词 88.49%）。ERP 客户名/产品编码必须从主数据表自动生成热词表 + 同音字兜底。
- 非流式 + VAD 分段比真流式更适合「说完一句执行一个动作」的场景。

### 架构结论（可复用到其他语音项目）
- 1.7B 要，但**只做动词分类（输出 3–5 token）**，别让它吐完整 JSON —— 纯 CPU 生成 80 token 要 3–5 秒，是体验杀手。
- 三层：L0 规则+用语表（85%，0ms）→ L1 0.6B 分类（+0.3s）→ L2 1.7B 兜底（<5%）。
- 安装包本体 240MB（纯 ASR，无 LLM 也能用），LLM 作可选组件首次使用时下载。
